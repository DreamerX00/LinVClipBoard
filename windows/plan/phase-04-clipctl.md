# Phase 4: Windows CLI Client (clipctl)

**Version**: v3.0.0-cli  
**Effort**: 2 days  
**Dependencies**: Phase 3 (Named Pipe IPC)

---

## Objective

Port the `clipctl` CLI client to Windows. On Linux, clipctl connects to clipd via a Unix domain socket. On Windows, it connects via a named pipe. The CLI interface itself is platform-agnostic.

---

## Tasks

### 4.1 Assess clipctl for Cross-Platform Readiness

Read `crates/clipctl/src/main.rs` and identify any Linux-specific code:

- [ ] Check for `libc` usage — none expected, CLI is pure Rust
- [ ] Check for `std::os::unix` — if present, gate with `#[cfg(unix)]`
- [ ] Check IPC connection code — must use platform trait
- [ ] Check for shell completion generation paths — may need adjustment

### 4.2 Update IPC Connection in clipctl

**`crates/clipctl/src/main.rs`:**

```rust
// Before (Linux-specific):
use tokio::net::UnixStream;

// After (platform-agnostic via shared):
use shared::ipc::connect;

#[tokio::main]
async fn main() -> Result<()> {
    let mut stream = connect().await?;
    // ... rest of CLI logic unchanged
}
```

The `shared::ipc::connect()` function from Phase 3 handles platform selection internally.
